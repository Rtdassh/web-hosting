Documentación de Arquitectura de Hosting

Bienvenido a la guía técnica oficial de la plataforma CloudPaaS. Esta documentación detalla los mecanismos de aislamiento, orquestación mediante Docker Engine y confinamiento de recursos para sitios web estáticos.

Nota de Producción: Todos los contenedores de inquilinos se ejecutan bajo el principio de menor privilegio, con UID/GID 101:101 y sistema de archivos montado en sólo lectura (:ro).

1. Arquitectura General

La plataforma implementa un desacoplamiento estricto entre el plano de control (FastAPI + PostgreSQL) y el plano de ejecución de inquilinos (Contenedores Nginx Alpine independientes conectados a la red virtual paas_instances_network). 

# Inspeccionar redes activas en el host
docker network inspect paas_instances_network --format '{{.Name}}: {{.Driver}}'

2. Control de Recursos (Cgroups v2)

Para garantizar la calidad ISO/IEC 25010 y prevenir ataques de denegación de servicio por agotamiento de recursos (Anti-OOM), se aplican cuotas por plan:

Plan Límite RAM Cuota CPU Sitios Permitidos
Free 128 MB 0.25 vCPU 1 Instancia
Developer 256 MB 0.50 vCPU 3 Instancias
Pro 512 MB 1.00 vCPU 10 Instancias

3. Directivas de Seguridad del Contenedor

Cada instancia se levanta con las siguientes banderas de seguridad del Docker Engine: 

--read-only \
--cap-drop ALL \
--security-opt no-new-privileges:true \
--user 101:101 \
--tmpfs /tmp:rw,noexec,nosuid,size=16m
Protección de Escritura: Cualquier intento de escritura sobre /usr/share/nginx/html arrojará el error Read-only file system a nivel de kernel de Linux.

4. Soporte para Subdominios Locales Simulados

El servidor soporta peticiones HTTP mediante el comodín *.localhost:PUERTO (RFC 6761), resolviendo de forma nativa hacia la dirección IP de loopback 127.0.0.1 sin requerir modificaciones en /etc/hosts.
